Сторона кандидата

Диплом есть. Доказательств нет.

  • Резюме описывает предметы и курсы, а не способность принимать инженерные решения.
  • Без опыта не берут, а опыт негде получить — замкнутый круг первого найма.
  • Студент не знает, где именно он слаб: обратная связь после отказа отсутствует.
  • Портфолио из учебных pet-проектов не отличимо от сотни таких же.
Сторона компании

Воронка забита шумом.

  • HR вручную просматривает сотни нерелевантных CV на одну позицию.
  • Первичный скрининг и проверка тестовых заданий съедают десятки часов инженеров.
  • Каждая ошибка найма junior-а — потерянный бюджет на онбординг и менторство.
  • Тестовые задания массово решаются чужими руками и LLM — сигнал недостоверен.

02 · Решение

Один сквозной контур: от симуляции до карточки кандидата

Вместо самопрезентации — фиксируемая работа. Вместо субъективного впечатления — структурированная оценка. Вместо стопки CV — упорядоченный список с доказательствами.

ШАГ 01

Кейс с ограничениями

LLM API подтягивает или генерирует профессиональную задачу с реальными B2B-рамками: бюджет, стек, архитектурные требования, сроки.

ШАГ 02

60 минут работы

Кандидат проектирует решение в рабочей среде под телеметрией. Ограничение по времени — часть условия задачи, а не формальность.

ШАГ 03

Смена вводных

В середине сессии условия контролируемо меняются — «у заказчика новое ТЗ». Так измеряется адаптивность, а не заученный шаблон.

ШАГ 04

Оценка и защита

Автопроверка по строгому JSON-рубрикатору плюс короткое ИИ-интервью по логике решения. На выходе — карточка кандидата.

      06 · ИИ-движок

      Оценка не «на глаз», а по воспроизводимой схеме

      Генерация кейсов

      LLM API формирует задачу из шаблона профессии и набора ограничений: бюджет, технологический стек, архитектурные требования, сроки. Каждая сессия — новая вариация, поэтому «слитые» ответы бесполезны.

      Тест на адаптивность

      Контролируемое изменение вводных в середине сессии показывает, умеет ли кандидат пересобирать решение и внятно объяснять компромисс, а не воспроизводить заученную схему.

      Обратная связь вместо отказа

      Каждый разбор возвращает кандидату конкретику: какие ограничения нарушены, какие решения слабо обоснованы, что изучить дальше. Это и есть продуктовая ценность бесплатного контура.

      Из чего складывается балл

      Модель оценивает не «впечатление», а пять заранее объявленных критериев с фиксированными весами. Кандидат и HR видят одну и ту же таблицу, поэтому оценку можно проверить и оспорить.

      • Логика решения25

        Задача разложена на части, выбор компонентов обоснован, а не перечислен.

      • Техническая корректность25

        Архитектура работоспособна, оценки нагрузки и латентности реалистичны.

      • Соблюдение ограничений20

        Учтены бюджет, срок, разрешённый стек и требование хранить данные внутри страны.

      • Адаптивность к смене ТЗ15

        Решение пересобрано после изменения вводных, компромисс назван словами.

      • Защита решения15

        Ответы на уточняющие вопросы согласуются с тем, что кандидат написал сам.

      На выходе: балл от 0 до 100, список доказательств по каждому критерию и рекомендации, что изучить дальше. Из штрафов вычитается телеметрия анти-чита, максимум 12 баллов.

      Показать машинный формат, в котором это уходит в API

      Так рубрикатор выглядит внутри системы: один и тот же файл версионируется, поэтому два кандидата на одну вакансию оцениваются по идентичной схеме, а не по настроению интервьюера.

      {
  "logic": { "weight": 25 },
  "technical_accuracy": { "weight": 25 },
  "constraints": { "weight": 20 },
  "adaptability": { "weight": 15 },
  "defense": { "weight": 15 },
  "penalty": "anti_cheat_telemetry_max_12",
  "output": "score_0_100 + evidence[] + next_steps[]"
}

      07 · Анти-чит

      Два уровня, которые делают результат достоверным

      Любая оценка навыков стоит ровно столько, сколько стоит доверие к ней. Поэтому достоверность в 1 SAGAT — не опция, а часть движка.

      Уровень 1

      Поведенческая телеметрия

      Среда фиксирует, как именно появлялось решение, а не только его текст.

      • Вставка из буфера заблокирована, каждая попытка логируется.
      • Фиксируется потеря фокуса окна — уход в другую вкладку виден.
      • Анализируется ритм печати: человеческий ввод неровный, копипаст — нет.
      • Длинные паузы и всплески объёма помечаются как аномалии.
      Уровень 2

      ИИ-интервью · Live Defense

      Сразу после сдачи ИИ-агент задаёт 2–3 уточняющих вопроса по логике конкретного решения.

      • Вопросы генерируются по тексту ответа, а не из общего банка.
      • Несогласованность защиты и решения снижает балл по критерию defense.
      • Чужое решение невозможно защитить: нужно понимать компромиссы.
      • Ответы прикладываются к карточке как доказательная база для HR.

      Бесплатный пилотный отбор на одну вакансию

      • Одна реальная вакансия. Берём ту, где поток резюме самый тяжёлый, и прогоняем полный контур без оплаты.
      • Считаем на их цифрах. Часы скрининга до и после, срок до первого интервью, доля релевантных кандидатов в shortlist.
      • Переход на подписку. Продаём не идею, а зафиксированную на пилоте экономию часов и бюджета найма.

      Как проходит пилот

      1. день 1Заявка и вакансия

        Берём требования к роли и текущие метрики воронки компании.

      2. дни 2–3Настройка контура

        Конструктор отбора собирает кейс, ограничения и рубрикатор под эту роль.

      3. дни 4–10Отбор кандидатов

        Симуляции, анти-чит, Live Defense, автоматическая оценка.

      4. день 11Отчёт и shortlist

        Ранжированный список с доказательной базой и расчёт сэкономленных часов.

      Что измеряем на пилоте: time-to-shortlist, часы ручного скрининга, доля кандидатов, дошедших до интервью, и доля офферов среди них.

      • Хакатон · MVP

        Один сквозной сценарий

        Профессия Junior AI Engineer: симуляция → ИИ-проверка по рубрикатору → финальная карточка-резюме кандидата для HR. Работающий контур целиком, а не набор экранов.

      • Этап 2

        Динамическая генерация вариаций

        Кейсы собираются через LLM API из библиотеки ограничений: каждая сессия уникальна, банк готовых решений теряет смысл.

      • Этап 3

        Полнофункциональный B2B-дашборд

        Создание отборов под вакансию, ранжированный shortlist, доказательная база по каждому кандидату, аналитика воронки и выгрузка в ATS.

      • Этап 4

        Расширение профессий и база кандидатов

        Новые роли по той же схеме рубрикатора, партнёрства с вузами для зачёта симуляции как практики, монетизация доступа к базе верифицированных навыков.
